## Clasificacion

Especificacion Temporal de Diseno.

## Objetivo documental

Este documento sirve como plano de la proxima microcirugia visual de Reservas, conserva la justificacion arquitectonica de la intervencion y permite auditorias futuras sobre las decisiones tomadas.

Su alcance se limita a la intervencion visual actual de las tres primeras pantallas de Reservas: bienvenida, tipo de vivienda y seleccion de sector.

Este documento no crea una nueva familia documental, no amplia CF-0001, no amplia CF-0002 y no constituye una autoridad arquitectonica permanente.

## 1. Objetivo perceptivo

Transformar la experiencia inicial para que se perciba como una capacidad de la Suite H - OperIA aplicada al proyecto AMENA. La identidad institucional debe gobernar la experiencia; la identidad de AMENA debe contextualizarla sin dominarla.

## 2. Que debe sentir el usuario durante el primer minuto

Debe sentir que entra a una experiencia confiable, sobria y guiada, no a un formulario comercial aislado. La aplicacion debe transmitir orden, acompanamiento, claridad y continuidad: cada paso existe para construir contexto util, no solo para capturar datos o seleccionar opciones.

## 3. Que debe comprender sobre H - OperIA y sobre AMENA

Debe comprender que H - OperIA es el sistema que estructura la experiencia, ordena la informacion y acompana la decision. AMENA es el proyecto especifico dentro de esa experiencia: el contexto inmobiliario, la oferta concreta y la identidad del cliente.

La lectura correcta debe ser: "estoy usando una experiencia H - OperIA para explorar AMENA", no "estoy en una app comercial de AMENA con estilos nuevos".

## 4. Que percepciones deben evitarse

Evitar que la pantalla parezca una landing page, un formulario generico, una app inmobiliaria aislada o una copia superficial del Admin. Evitar que AMENA absorba toda la identidad visual. Evitar que H - OperIA aparezca solo como estilo implicito sin presencia perceptiva. Evitar que el progreso parezca un contador mecanico sin sentido de recorrido guiado.

## 5. Criterios de exito

La microcirugia posterior sera exitosa si una persona puede reconocer en el primer minuto:

* pertenencia visible a H - OperIA;
* AMENA como contexto del proyecto, no como sistema dominante;
* recorrido guiado y no simple formulario;
* jerarquia clara entre Suite, proyecto, paso y accion;
* captura de datos y elecciones como construccion de contexto operativo;
* continuidad perceptiva entre las tres pantallas;
* uso de AR-VIS-001 y CF-0001 como arquitectura global, no solo como tokens visuales.

## Criterio de cierre

Esta especificacion se considera cerrada cuando la microcirugia correspondiente haya sido implementada, validada humanamente y publicada. A partir de ese momento permanecera unicamente como evidencia de diseno y no continuara evolucionando, salvo correccion de errores objetivos.
