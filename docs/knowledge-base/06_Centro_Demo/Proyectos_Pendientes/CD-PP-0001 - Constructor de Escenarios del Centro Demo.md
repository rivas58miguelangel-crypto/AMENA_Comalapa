# CD-PP-0001 - Constructor de Escenarios del Centro Demo

## Estado

Proyecto pendiente del Centro Demo.

Debe desarrollarse despues de concluir la FASE 06 del Centro Demo.

No forma parte del Demo Ejecutivo actual.

## Objetivo

Crear un modulo interno del Centro Demo que permita preparar una nueva demostracion ejecutiva para una empresa o proyecto distinto, sin modificar manualmente el codigo fuente.

El objetivo es convertir la preparacion de una nueva demo en un proceso guiado, validado y repetible.

## Naturaleza del proyecto

Este proyecto pertenece exclusivamente al Centro Demo.

No administra clientes reales.

No configura produccion.

No debe confundirse con la parametrizacion white label de produccion.

Su proposito es crear escenarios temporales de demostracion.

## Flujo operativo esperado

1. Finalizar el recorrido escenico del Centro Demo hasta FASE 06.
2. Abrir el modulo de preparacion del siguiente escenario.
3. Crear nueva empresa demo.
4. Crear nuevo proyecto demo.
5. Reiniciar unicamente la informacion especifica del escenario anterior.
6. Cargar o indicar fuentes de informacion.
7. Ejecutar extraccion asistida.
8. Revisar ficha estructurada.
9. Aprobar datos.
10. Generar escenario.
11. Inyectar el escenario en el ecosistema demo.
12. Dejar el Centro Demo listo para una nueva presentacion ejecutiva.

## Fuentes admitidas

El constructor podra recibir:

- URL del sitio web del prospecto.
- PDF comercial.
- Brochure.
- Excel de precios.
- Excel de inventario.
- Carpeta de fotografias.
- Logos.
- Videos.
- Textos comerciales.
- Documentos Word.
- Presentaciones.
- Prompts de configuracion escritos por el consultor.

## Extraccion asistida

El modulo debera extraer o sugerir:

- Nombre de empresa.
- Nombre de proyecto.
- Tipo de proyecto.
- Ubicacion.
- Modelos o productos.
- Precios.
- Inventario demostrativo.
- Amenidades.
- Fotografias relevantes.
- Textos comerciales.
- Preguntas frecuentes.
- Senales comerciales potenciales.
- Objeciones probables.
- Datos utiles para Marta.
- Datos utiles para H-OperIA Intelligence.

## Ficha estructurada del escenario

Antes de inyectar datos, el sistema debera mostrar una ficha con:

- Empresa demo.
- Proyecto demo.
- Descripcion.
- Modelos.
- Precios.
- Inventario.
- Fotografias.
- Amenidades.
- Mensajes sugeridos.
- Datos simulados.
- Evidencias demo.
- Hallazgos esperados.
- Datos faltantes.
- Riesgos o supuestos.

## Validacion humana obligatoria

Nada debera inyectarse automaticamente sin aprobacion.

El consultor debera poder:

- Corregir.
- Eliminar.
- Agregar.
- Reemplazar.
- Aprobar.

## Inyeccion demo

Una vez aprobado, el escenario podra alimentar:

- App de Reservas demo.
- Centro Demo.
- App de Vendedoras demo.
- Mensajeria demo.
- Marta demo.
- H-OperIA Intelligence demo.
- Evidencia operacional demo.
- FASE 05.
- FASE 06.

## Reinicio de escenario

El sistema debera permitir limpiar o reemplazar unicamente los datos del escenario demo activo.

No debe borrar conocimiento estructural.

No debe modificar el codigo.

No debe afectar configuraciones productivas.

## Auditoria

Cada escenario demo debera registrar:

- Fecha de creacion.
- Fuentes utilizadas.
- Archivos cargados.
- Prompts usados.
- Datos aprobados.
- Supuestos.
- Version del escenario.
- Estado de inyeccion.

## Relacion con el Plan Maestro

Este proyecto:

- Se trabajara despues de concluir FASE 06.
- Pertenece al Centro Demo.
- Sirve para preparar nuevas presentaciones comerciales.
- No debe mezclarse con la arquitectura white label de produccion.
- Es un puente para que H-OperIA pueda demostrarse a multiples empresas sin reconstruir manualmente el demo.
